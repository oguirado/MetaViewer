**D3. Random IDs, chosen IDs and correlation [DERIVED]**

Assume N independent uniform draws from a set of size M. Each pair collides with probability 1/M. There are N(N−1)/2 unordered pairs, so the union bound gives P(any collision) ≤ min(1,N(N−1)/(2M)). Sequentially avoiding the previous k values has probability 1−k/M, so for N≤M the exact probability of no collision is the product over k=0..N−1 of (1−k/M). Using 1−x≤exp(−x), collision probability is at least 1−exp(−N(N−1)/(2M)). Thus N on the order of sqrt(M) produces constant collision probability; it is not an impossibility guarantee below that scale.

Node randomUUID returns UUIDv4. Its 128-bit layout reserves version/variant bits and leaves 48+12+62=122 random bits. [CITED: Node API and RFC 9562 §5.4.] The idealized actual model is M=2^122, not 2^128. With N=64 the upper bound is 2016/2^122. The birthday scale is 2^61; hypothetical unrestricted 128 random bits would instead give 2016/2^128 and scale 2^64. The generator's actual entropy/independence was not measured.

For renderer-chosen request_id there is no randomness assumption: choosing “r” twice makes duplication certain after two choices. Only under an additional uniform fixed-length L model would M=95^L and q guesses against a uniformly unknown id have upper bound min(1,q/95^L). The actual API does not promise that model and does not use request_id as authorization.

Captures allocate fresh host UUID keys and retain the original request id separately, so deliberately duplicated renderer ids still correlate through distinct invocation promises/host keys. Intent/proposal currently pending duplicates refuse at hostBindings.js:742. Historical reuse after completion is not globally forbidden. A forced RNG collision on the capture allocation would overwrite pending.set because there is no collision-retry guard; this disproves unconditional issue-once, but does not establish a feasible renderer attack. T03 injects the condition on paper. A peer's numeric pid also has no random-UUID model: SO_PEERCRED authenticates the connected fd's credentials, supplemented by peer-inode binding. No PID-reuse probability or executable-identity theorem follows from the source.

**D4. Finite coverage design and limits [DERIVED]**

Define a declared matrix with method factor M={0..5}, malformed-field-class factor C={0..11}, mode N={normal,nested}, and boundary B={preload,main}. C means: baseline; missing required item; extra enumerable key; symbol key; hidden key; accessor; wrong primitive/container; wrong schema; invalid identifier; invalid enum; lower-bound violation; upper-bound violation. For argumentless methods the field mutations must be explicitly marked inapplicable or translated to an unexpected-argument arity case; they cannot silently count as twelve independent meaningful field tests.

For the unconstrained syntactic factor matrix, create one row per (m,c), set n=(m+c) mod 2, and b=(m+floor(c/2)) mod 2. Every M×C pair appears once. For fixed m, c=0..3 supplies both n and b values and all four N×B combinations. For fixed c, even/odd m supplies each N and each B value. Therefore every pair projection is covered. Any pairwise array needs at least 6×12=72 rows to cover M×C; this construction attains 72 for these declared factor levels. It is an exact combinatorial result for the matrix, not minimal semantic test coverage after applicability constraints.

It necessarily misses the M×C×N triple with n opposite to the constructed parity for each fixed (m,c). A mutant that fails only for one such method/class/mode triple survives the pairwise set. Full four-factor enumeration would require 6×12×2×2=288 rows. For the four input kinds using the same even-sized construction, the corresponding pairwise count is 4×12=48 versus 4×12×2×2=192 full rows. To exercise both validator implementations on every payload, run both boundaries explicitly rather than confusing factor coverage with per-payload parity.

The shipped capture.test.js:82–84 “main/preload” case calls only main assertCaptureCall on two screenshot inputs. It does not establish the equality theorem by execution. captureTransport fixtures use valid canned success metadata; missing stop sealed=true, method mismatch, each malformed reply row and byte-boundary mutation must be independently asserted. w3-human-input's newer ASCII coalescing tests omit the three-way conjunction escaped text × coalescing × near-limit length. R3-T4-004 is a concrete missed interaction; no claim of a measured mutation score is made.

The construction also works for nine intent operations (M=0..8) and the two settings operations load/save (M=0..1): fixed c still sees both parities of m, and fixed m sees all necessary c classes. Their pairwise lower bounds and attained counts are 9×12=108 and 2×12=24, versus 432 and 96 full four-factor rows. Argumentless settings.load retains the same applicability warning.

For strength three, use both n=0,1 for every (m,c), and set b=(n+m+floor(c/2)) mod 2. Each M×C×N triple occurs; changing n also covers M×C×B. For fixed m,n, choosing c of opposite floor(c/2) parity covers both b values, so M×N×B is covered. For fixed c,n, even/odd m covers both b values, so C×N×B is covered. All four triple projections are covered. M×C×N requires at least 2|M||C| rows; this construction attains that bound: 144 capture, 96 input, 216 intent and 48 settings rows. These exact counts concern the declared unconstrained matrix; they do not assert all semantic bugs are three-factor bugs.

Batch event count is at most 32 and normalized JSON UTF-8 size at most 16,384. See authorityWire.js:108–198 and preload.js:515–607.

A record accessor or hidden/symbol key is refused by descriptor/cardinality checks; sparse arrays and accessor indices are refused. Reading kind before its descriptor check is not proof that Electron transports accessors: native IPC cloning/JSON is a separate domain. NaN, infinity and huge unsafe integers refuse; −0 is admitted at zero-allowed numeric fields and serialized as 0. That is integer-zero semantics, not a demonstrated gap. The two source regex spellings using dollar versus negative lookahead have equivalent end-of-input behavior here.

The refusal output set is exactly {NOT_IN_CONTROL,SURFACE_UNKNOWN,STALE_STREAM,LIMIT,NESTED_DISPLAY_ONLY,SCHEMA,CORE_UNAVAILABLE}. At main admission, recent timestamps retain only now−t<1000, and the next request is refused if there are already 60 retained entries. Assuming a nondecreasing clock, at any successful insertion the new rolling one-second window has at most 60 entries: induction removes old entries, checks count≤59, then adds one. Thus for one fixed id at most 60 admitted-to-core batches lie in that rolling window; at most 60×32=1920 input events can be forwarded in those batches. The cap is on main IPC batches, not individual renderer calls after coalescing, and says nothing about distinct-id cardinality.

For R3-T4-002, start from an empty rate map and use a fresh unknown id for each request. The request adds exactly one new key before core refusal, and no completion path deletes that key. By induction, after N sequential refusals cardinality=N. No pending-call cap is reached. The same induction applies to preload queue-state insertion; host capture lookup entries also lack deletion, and terminal input queue cleanup is incomplete. Strictly, the identifier language is finite: there are 62 choices for its first character and66 for each later character, so its size is 62 times the sum of 66^k for k=0..127, equal to 62(66^128−1)/65 by multiplying that sum by 66 and subtracting it. Thus map growth is linear in the distinct admitted ids up to that enormous language bound; “unbounded” here means no enforced operational/live-surface cap, not a mathematically infinite identifier set.

For R3-T4-004, the compact JSON wrapper without events contributes 81 bytes for the stated fields. Each newline-filled type event has 1024 raw bytes, but JSON escapes each newline to two ASCII characters. Its serialized event size is 2073 bytes. Therefore a seven-event batch has 81+7×2073+6=14,598 bytes. Two such batches are independently below 16,384. These lengths were independently evaluated as arithmetic/serialization oracles, without executing product code.

Let a slot's deadline be D=3 seconds and maximum scheduling lateness J. Its occupation time is at most D+J if that lateness premise holds. For C=64 concurrently held non-input slots, the integral of occupied slots until their deadlines is at most 64(3+J)=192+64J slot-seconds. The newer host counts input separately: for 64 stable surfaces and one in-flight input action each, 64 non-input + 64 input = 128 simultaneous entries, giving a conditional 384+128J slot-second wave bound. Terminal churn without cancellation invalidates that stable-surface premise; do not state a universal 128 cap. Surfaces and subscribers have no three-second expiry, so 64 held for T seconds consume 64T slot-seconds, unbounded over lifetime.

A queue cap also does not imply a three-second end-to-end batch deadline. With Q single-event requests ahead and one wire request served at a time, final residence can approach (Q+1)D before jitter. In the preload, one request can be active while 255 single-event requests are queued ahead of the final accepted request, which becomes the 256th queued request. Thus Q=256 includes the active request ahead, and 257×3=771 seconds is a conditional residence under serial timeouts that preserve the input session. The host's own queue includes its active head in the 256-event count; the 771-second example is not attributed to that host queue alone. This is a conditional scheduling counterexample to treating a per-wire timer as a whole-queue SLA, not a measured delay. Whether an entire input batch is required to satisfy the same three-second budget is an unresolved product-contract interpretation.

For a queue-size identity without importing an inapplicable paper: over observation interval [0,T], integrate the sum of indicators that each job is present. Exchanging the finite sum and integral gives sum of each job's residence intersection with [0,T]. Dividing by T yields average occupancy. Replacing that finite identity by an arrival-rate times mean-residence formula additionally requires stable long-run limits and boundary terms negligible relative to T; those assumptions are not supplied by this code. The retained-map and subscriber counterexamples therefore cannot be dismissed with a steady-state queueing formula.

A timer requested for delay d runs at d+J, where J≥0 is scheduling lateness. A hard upper bound requires an independent bound on J; no such bound follows from setTimeout. The generic coreLauncher.js:927–943 has separate connect and hello timers: with each configured to 10,000 ms, connect at 9,999 ms and hello 9,999 ms later is a 19,998-ms logical counterexample to treating those stages alone as a single 10-second timer. The reviewed production template corrects that stacking shape: package.js:622–630 sets one deadline D=now+B, default B=10,000 ms, then :658–673 gives main only D−now. The positive MV_PKG_BOOT_BUDGET_MS override also changes B; non-finite/extreme values need a policy test. The default budget is a logical deadline, not a measured whole-process launch guarantee.

**D10. Flakiness and the distinction between a timer and a statistical guarantee [DERIVED]**

Let X_i be independent Bernoulli failure indicators with common probability p. If n trials show zero failures, the probability of that observation for p≥epsilon is at most (1−epsilon)^n. To reject that hypothesis at one-sided confidence 1−delta, require (1−epsilon)^n≤delta, or n≥ceil(log(delta)/log(1−epsilon)). For epsilon=.001 this is 2995 trials at delta=.05 and 6905 at delta=.001. These are confidence statements under iid observations, not proof p=0, and repetitions do not reduce the actual underlying false-failure rate. No such observations were collected.

For a full concentration derivation, let X lie in [0,1] and g(lambda)=log E(exp(lambda(X−E X))). Then g(0)=g'(0)=0; g'' is the variance under exponential tilting. For any distribution supported in [0,1], E((X−1/2)^2)≤1/4 and variance minimizes centered second moment, so g''≤1/4. Integrating twice gives g(lambda)≤lambda^2/8. Independence multiplies moment-generating functions; Markov's inequality then bounds P(mean−p≥epsilon) by exp(−lambda n epsilon+n lambda^2/8). Choosing lambda=4epsilon gives exp(−2n epsilon^2). Apply the same reasoning to −X and union-bound the tails: P(abs(mean−p)≥epsilon)≤2exp(−2n epsilon^2). Therefore n≥ceil(log(2/delta)/(2epsilon^2)); epsilon=.001 and delta=.001 gives 3,800,452 trials. This is a general estimation-error bound, not a proposed number of slow smoke reruns.

CI scheduling and load often violate the independent identical-trial premise, so no numerical confidence claim is made for the shipped wall-clock tests. Virtual clocks should decide state-machine boundaries; explicit barriers should decide causal ordering. Keep real Electron/package/RSS runs separately as environment evidence. Nested startup's 15,000-ms configured race versus a 20,000-ms test allowance implicitly leaves 5000 ms for scheduling/cleanup, but supplies no proof that it is enough. An RSS sampler at nominal 20-ms intervals measures a sampled maximum, which is at most the continuous maximum; a short peak between samples can be missed. A sustained touched-allocation negative control is useful for its stated leak case, not every transient allocation.
