# T1 CORE — Rust Authority Core Hardening Report

## Summary

This report documents the T1 CORE surface hardening for `metaviewer-core` 0.1.1 on branch `jules/test-t1`.
The Rust authority core implements action admission with six refusal reasons, lease and budget tracking, JSONL journaling with sha256 hash chains, fsync durability, deterministic replay, owner-only Unix sockets, and NDJSON framing.

All seven test obligations defined in the specification have been implemented through six new comprehensive integration test suites (`core/tests/*.rs`). All tests pass cleanly across consecutive runs alongside all existing tests, workspace clippy lints (`-D warnings`), and formatting checks. Product code (`core/src/**`) and existing test suites were left strictly untouched.

## Tests written or proposed

### Test Suites Created

1. **`core/tests/journal_tamper.rs`** (Obligation 1 — Hash-chain tamper matrix)
   - `tamper_matrix_byte_flips_and_exit_codes`: Tests bit/byte flips in session record fields and `prev_sha256`, verifying `scan`, `Authority::recover`, and `mv-replay` exit code 2 (`Corrupt`).
   - `tamper_matrix_middle_sidecar_deletion`: Verifies `scan` fails with `JournalError::Io` and `mv-replay` exits 2 when an event sidecar is deleted.
   - `tamper_matrix_tail_truncation`: Verifies tail truncation fails hash-chain verification and returns exit code 2.
   - `tamper_matrix_checkpoint_fields`: Mutates `count`, `tail`, `archive`, and `genesis` in `checkpoint.json`, confirming corruption detection.
   - `corollary_2_reforgery_and_anchor_demonstration`: Recomputes a forged journal suffix and checkpoint, demonstrating local verification vs. external anchor detection, and verifies witness corruption exit code 4 (`Witness`).

2. **`core/tests/decode_fuzz.rs`** (Obligation 2 — Decoder fuzz + exact boundaries)
   - `exact_boundaries_depth_keys_string_envelope_integers_arrays`: Tests boundary pairs for depth (32/33 -> `DepthExceeded`), keys (256/257 -> `KeyLimitExceeded`), string length (65536/65537 -> `StringLimitExceeded`), frame bytes (1000 -> `Oversized`), wire integers (`MAX_WIRE_INTEGER` 9007199254740991 vs `+1` -> `OutOfBounds`), and array commas (4095/4096 -> `ArrayLimitExceeded`).
   - `hostile_shapes_and_exact_errors`: Tests duplicate keys, escape-spelled duplicate keys (`\u0061`), trailing bytes, BOM prefix (`EF BB BF`), NUL byte handling, empty vs blank inputs, and unknown schema versions.
   - `transport_roundtrip_and_frame_fuzz`: Differential testing between `write_frame` and `read_frame`, plus CR-only separator handling.
   - `seeded_fuzz_harness_2000_runs`: 2000 seeded PRNG fuzz runs testing random inputs, depth trees, key maps, and character mutations without panics.

3. **`core/tests/recovery_crash.rs`** (Obligation 3 — Crash/restart recovery)
   - `scripted_sequence_with_simulated_crashes`: Drives a full lifecycle (Surface -> Frame -> Propose -> Dispatch -> Receipt -> TakeControl -> ReleaseControl) and verifies crash recovery, identical double recovery digests (SW-0177 Claim 1 Idempotent Redo), and digest equality with `scan`.
   - `crash_scenarios_and_atomicity`: Tests orphan event sidecar detection (`JournalError::Unsealed`), torn tails, and stale `checkpoint.next` cleanup.
   - `aries_fsm_transition_table_mapping`: Maps the ARIES recovery FSM transitions (START -> ANALYSIS -> REDO -> UNDO -> DONE / PARADA) and verifies absorbing fault state behavior.

4. **`core/tests/admission_permutations.rs`** (Obligation 4 — Permuted admissions + mutant check)
   - `fisher_yates_50_permutations_and_verdict_determinism`: Generates random valid input sequences and runs 50 seeded Fisher-Yates permutations across independent surfaces, asserting identical verdict sequences and identical final domain snapshots.
   - `permutation_divergence_exact_rules`: Verifies controlled divergence rules for dependent inputs (duplicate proposal -> `POLICY`, stale frame -> `STALE_FRAME`).
   - `lease_race_3_contenders_and_display_conflicts`: Tests lease races with 4 concurrent contenders (exactly 1 winner) and display conflict pairs across distinct surfaces (`LOCKED_BY_OTHER`).
   - *Mutant Check*: Temporary off-tree deletion of `LockedByOther` check in `admission/mod.rs` was executed; `lease_race_3_contenders_and_display_conflicts` failed immediately, confirming mutant kill.

5. **`core/tests/admission_atomicity.rs`** (Obligation 5 — Failure atomicity)
   - `failure_atomicity_and_refusal_matrix`: Tests all six refusal reasons (`STALE_FRAME`, `SURFACE_NOT_AGENT_CONTROLLED`, `LOCKED_BY_OTHER`, `OUT_OF_BOUNDS`, `BUDGET_EXCEEDED`, `POLICY`) and asserts that `domain_snapshot` (surfaces, leases, pending, draining, budget, epoch) remains 100% byte-identical after each refusal.
   - `error_paths_leave_bytes_untouched_and_poison_handle`: Verifies that `JournalError` paths leave `state` snapshot bytes untouched, storage publish failure poisons the handle until recovery, and recovery restores verified state.

6. **`core/tests/socket_hostile.rs`** (Obligation 6 — Socket + handshake hostility)
   - `hostile_socket_binding_and_symlinks`: Verifies 0700 runtime directory and 0600 socket mode under hostile umask, refusal of parent directory symlinks (`UnsafeRuntimeDir`), preservation of regular files/symlinks (`NotSocket`), and live socket connect refusal (`LiveSocket`).
   - `handshake_hostility_version_pin_identity_timeout`: Verifies successful handshake, double hello refusal (`AlreadyReady`), pin mismatch refusal (`PinMismatch`), and acceptance instant deadline enforcement (`handshake_at` timeout).
   - `mv_replay_cli_exit_codes_and_verify_only`: Tests `mv-replay` CLI exit code 0 on valid journal with digest match, exit code 2 on corrupt journal, and silent exit 0 under `--verify-only`.
