## Area 1: core journal end (`journal_end.rs`, `serve/mod.rs`, `journal/mod.rs`)

### `env.clone()` and the x64 latency budget: clean

- Frame pixels never travel in the envelope. `FrameRef` points at `/dev/shm`. The
  clone copies a small set of strings.
- A throwaway release-build test parsed a daemon `frame_ref/v0.2` envelope of 563
  bytes [MEASURED] and timed 200000 [MEASURED] iterations of each operation:

  | operation | time per envelope |
  |-----------|-------------------|
  | `clone` | 289 ns [MEASURED] |
  | `serde_json` decode (already on the path) | 283 µs [MEASURED] |
  | serialize | 717 ns [MEASURED] |

- A 20 Hz producer [TARGET] adds about 5.8 µs per second per tile [MEASURED, derived].
- The budget is 10 fps minimum and 2000 ms maximum silence for hosted x64
  [CITED: `tests/e2e/e2e14_perf.test.js:15-28`]. The clone uses under 0.001% [MEASURED,
  derived] of a 100 ms frame period [TARGET].
- Non-frame messages are bounded by `MAX_FRAME_BYTES` = 1048576 [CITED:
  `core/src/wire/mod.rs:17`].
- Unchecked: `e2e14_perf` itself was not run, and the GitHub-hosted runner was not
  measured.

Existing tests: `cargo test --release -p metaviewer-core --lib journal` gave 64 passed,
0 failed [MEASURED].

Checked and clean:

- Connect path (`mod.rs:2653-2683`): the end is decided before the daemon is inserted,
  and the first destroy goes out after `Hello`.
- `outbound_at` does not journal, so notices cannot themselves hit capacity.
- The `retire` early return during an ended session.
- Marker load: mismatched, empty and unreadable hints are moved aside.
- The destroy barrier: exact terminal refusal, "already in progress", and the grace

### C1: a timer-driven capacity refusal skips the clean session end

- **Where:** `core/src/serve/mod.rs:2044-2045` (`poll_headless_at` and
  `poll_guest_command_at`), propagated by `poll_tool_waiters_tick()?` at
  `mod.rs:2810` and `mod.rs:2844`.
- **Effect:** the journal is full and the next write comes from a deadline rather
  than a routed message. That write returns `JournalError::Policy`, but only
  `route_at_with_pixels` (`mod.rs:1299-1310`) and the connect path map `Policy` to
  `end_full_journal`. So `journal_end` stays unset. The connection task returns the
  error and its transport closes. The state is unchanged, so the next tick on every
  other connection repeats the error. No peer gets `JOURNAL_FULL`, no ordered stop
  is sent, and no marker is written. This contradicts `docs/JOURNAL_END.md`
  ("A full journal permanently closes admission ... Cleanup still starts").
- **Sequence:**
  1. An agent submits a headless `create`. The deadline is 35 s [MEASURED] after receipt.
  2. Accepted records fill the journal to `MAX_RECORDS` = 100000 [CITED:
     `journal/mod.rs:652`], or to the 64 MiB archive limit [CITED], with no further
     routed message.
  3. The deadline passes, and `mark_headless_unknown` appends `HeadlessUncertain`,
     which gets `Policy`.
  4. The peers' transports close one by one. The same applies to
     `GuestCommandUncertain` and to the rewind poll.
- **Proof:**
  - Run: a throwaway test in `journal_end_tests.rs` set the record limit to the
    current `core_seq` and called `poll_tool_waiters_at(deadline + 1)`. It printed
    `poll_err=Some("Policy") journal_end_set=false`.
  - Read: the transport close after the error.
- **Reach:** this needs a full journal, so a short judge demo is unlikely to hit
  it. Long sessions can.
- **Smallest fix:** in `poll_tool_waiters_at`, catch `JournalError::Policy` from the
  two poll calls and enter the same end path, then return `Ok`. `end_full_journal`
  needs a variant without an envelope: flush, set `journal_end`, persist the marker,
  notify, then `start_next_journal_stop`.

### U1: demo control accepts requests the v0.3 schema rejects

- **Where:** `ui/electron/demoControl.js:11-12`, through `ui/electron/preload.js:118`.
- **Effect:** `assertButtonCall` checks only `args.length`, so a non-array value gets
  through:
  - `"args":""` for `demo.stop`;
  - `{"length":1,"0":{"site":"site"}}` for `demo.check`.

  Main then stops the recording or spawns the check, although
  `contracts/v0.3/demo_control.schema.json` requires an array. This breaks the
  contracts-first law (`LAWS.md`). It grants no new capability: the socket is
  private to the same user.
- **Proof (run):** the host replied `ACCEPTED` to both requests, and `jsonschema`
  replied `REJECTED` against the same schema.
- **Smallest fix:** add `!Array.isArray(row.args) ||` to the guard on line 11.

- **Effect:** the remote reply text already ends in `\n`, and `print` adds another.

- **Proof (run):** the remote stdout ended `` ```\n\n `` and native ended `` ```\n ``.
- **Smallest fix:** `print(text, end='')` in the remote branch.

## Area 3: native lock probe (`capsule/process.go`, `frames/subscriptions.go`)

Checked and clean:

- **Descriptor leak:** after a successful open, every path closes the descriptor
  through `defer`, and `O_CLOEXEC` is set. The descriptor count was unchanged
  across 21000 [MEASURED] probes covering the free, busy and wrong-mode paths.
- **Frame poll:** `native_busy` resets the loss counters and writes no warning.
- **Liveness:** `native_busy` is not counted as absence.
- **Contracts:** `native_busy` is a fault code carried in the existing
  `surface_event` error code field, not a new message type.
- **Tests:** `go test ./internal/capsule/... ./internal/frames/...` passed.

### G1: probe against probe gives a false `native_busy`

- **Where:** `daemon-adapter/internal/capsule/process.go:94` (`LOCK_EX|LOCK_NB`).
- **Effect:** one `MV_SRF_STATE_DIR`, and so one `control.lock`, is shared by every
  native capsule in the adapter. `Run` has no mutex, so two frame commands that
  overlap exclude each other. Frame poll and liveness absorb this. These paths turn
  it into a user-visible failure (read):
  - the create first capture (`internal/daemon/dispatch.go:92-94`): the new capsule
    is destroyed and the create is reported failed;
  - the post-input capture (`internal/daemon/environment.go:977-982`, via
    `settleInput`): the receipt says the input failed after it already ran;
  - state refresh and record capture.
- **Sequence:** capsule X is polling frames. The user creates capsule Y, or an agent
  sends input to Y. Y's capture probe overlaps X's probe, and Y's operation fails
  with `native_busy` while no recorder holds the lock.
- **Proof (run):** two goroutines each ran 200000 [MEASURED] probes on a free lock,
  and 29173 of 400000 [MEASURED] returned `native_busy` in a tight loop. The rate at
  production poll intervals was not measured.
- **Smallest fix:** probe with `LOCK_SH|LOCK_NB`. In the same test that gave 0 of
  400000 [MEASURED] busy, and it still detected an exclusive holder. This assumes
  the native recorder holds `LOCK_EX`; that is ABSENT — do not invent.

### Can the probe make a native control operation fail?

ABSENT — do not invent: the native viewer source is not in this repo.

- If native control takes `control.lock` with a non-blocking lock, yes. A simulated
  native `LOCK_EX|LOCK_NB` caller got `EWOULDBLOCK` in 29341 of 200000 [MEASURED]
  tight-loop attempts.
- If it uses a blocking `flock`, the probe only delays it by about the length of
  one probe.
- With the G1 fix, the remaining conflict is with a native non-blocking exclusive
  lock only. `/proc/locks` inspection would avoid even that.

Run: a successful smoke through the real `executeSmoke`, with Electron 44.9.2

### S1: the install smoke aborts when the judge home path is long (new in this diff)

- **Where:** `scripts/judge/metaviewer-judge.sh:419`, together with `TMPDIR:clean` at
  `ui/tools/package.js:2783`, `:2815`, `:2841` and `:2868`. The lock call is
  `app.requestSingleInstanceLock()` (`ui/electron/main.js:2262`).
- **Effect:** Electron puts its single-instance socket at
  `$TMPDIR/scoped_dirXXXXXX/SingletonSocket`, 33 bytes [MEASURED] past `TMPDIR`. With
  the default `MV_JUDGE_HOME`, `clean` is 66 bytes plus the user name length
  [MEASURED]. Any user name of 9 characters or more [MEASURED] goes past the
  `sun_path` limit of 108 bytes [CITED: Linux `sockaddr_un`]. Electron then aborts
  with `Socket path too long` and rc 133 [MEASURED], the judge prints `JUDGE_SMOKE`,
  and the printed fix (DISPLAY, xvfb-run, AppArmor) points the wrong way.
- **History:** before this diff, `clean` lived under `/tmp` and children had no
  `TMPDIR`.
- **Sequence:** user `reviewer1` with the default home runs `metaviewer-judge.sh
  install`, and the smoke fails. `/home/reviewer/...` is exactly 74 bytes
  [MEASURED], which is the last length that passes.
- **Proof (run):**
  - Electron 44.9.2 with `requestSingleInstanceLock()` under `xvfb-run -a`:
    `TMPDIR` of 74 bytes gave rc 0 and `LOCK true`; 75 bytes gave rc 133 and
    `Socket path too long` [MEASURED].
  - The result was reproduced twice, independently.
- **Not checked:** the packaged release tarball end to end (no tarball here), and
  whether `$XDG_RUNTIME_DIR/metaviewer/core.sock` under `clean` (1 byte [MEASURED]
  tighter) is bound during the smoke.
- **Smallest fix:**
  1. Have the judge create a short private smoke directory (`mktemp -d
     /tmp/mvj.XXXXXX`), record its path under `run/` so `stop` still checks it, and
     pass that as `TMPDIR`.
  2. Also refuse early with a named code when `clean` plus 34 bytes [MEASURED]
     would reach 108 [CITED].

### S2: residue from an interrupted smoke makes every later `stop` fail

- **Where:** `scripts/judge/metaviewer-judge.sh:416-418` (`mkdir -p` only),
  `metaviewer-judge.sh:798-803`, and `docs/JUDGE_TROUBLESHOOTING.md` (no row).
- **Effect:**
  - When node dies before its `finally` runs (kill -9, the OOM killer, a terminal
    hang-up), a pid record stays in `smoke-processes/` and `mv-clean-*` stays in
    `smoke-tmp/`.
  - Install never reconciles or clears them, so every later `stop` returns rc 2
    [CITED: `judge.sh:798-803`], including after a clean reinstall with a
    successful smoke.
  - The printed fix has no tool behind it, and no judge document mentions rc 2 or
    smoke state.
- **Proof (run):**
  - `kill -9` on node during a smoke left one pid record and
    `mv-clean-*/{host-runtime,xvfb-run.*}`.
  - A later smoke resolved and its `clean` was removed, yet `stop` printed 2
    [MEASURED] `JUDGE_STOP_LEAK` lines and returned rc 2 [MEASURED].
  - The killed group's Xvfb kept running.
- **Smallest fix:**
  1. At install start, check each pid record against `/proc/<pid>/stat` (start
     time and process group).
  2. When the group is gone, delete the record and its `mv-clean-*`.
  3. Add a troubleshooting row with the manual steps.

## Area 5: remembered cell restore (`WallWorkspace.vue`)

### W1: a remembered cell outside the current grid is dropped

- **Where:** `ui/src/wall/WallWorkspace.vue:1184`. The hint is stored as `{col,row}`
  with no grid size.
- **Effect:** after the custom grid shrinks, the range check skips the restore. The
  capsule reopens docked and splits the custom layout. The grid-preset path
  (`nextFloatingCell`) falls back to the first free cell for the same hint
  instead, so the two paths disagree.
- **Sequence:**
  1. Float-snap a capsule to column 3 of a 3x2 grid.
  2. Set columns to 2.
  3. Close and reopen the capsule: it opens docked.
- **Proof (run, mocked Dockview):** the fewer-cells case returned `undefined`
  (docked), and the preset fallback for the same hint returned cell `(0,0)`.
- **Smallest fix:** clamp the hint instead of skipping it:
  `{col:Math.min(hint.col,grid.cols-1),row:Math.min(hint.row,grid.rows-1)}`.
- **Not checked:** clamping in the real Dockview.
