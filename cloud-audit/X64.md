x86_64 Linux while still working on arm64. Base `v0.2.5` = `origin/main` =
`7721915c`; audited head `a7c36e9d` (one commit, 1852 files changed [MEASURED]).
Audit host: x86_64 cloud container. **Nothing here was verified live**: this
machine has no display stack, no docker daemon and no KVM, and runs as root.
Every finding is a candidate for the conductor to check on a real x64 machine.

## Summary

- No release blocker for x64 base capsules (browser, Program, Host program,
  Desktop window) was found in product code. Read only; not verified live.
- One arch-bound **test** fails on x64 and passes on arm64 (F1, confirmed by running).
- Several arch-neutral reds exist on this branch (contract fixture corpus pins,
  channel-order and Electron-harness tests). They fail on arm64 too, so they are
  not x64 regressions, but they would turn x64 CI red and can hide a real one (F2, F3).

## Findings

### F1. Guest-command observation transport test only passes on arm64 (confirmed by running)

- File: `ui/test/guest-command-observation-transport.test.js:30` asserts
  `binding.core.guestCommand.status().available === true`. The fixture sets only
  `MV_GUEST_COMMAND_ONLY=1` and leaves the arch at its default.
  `ui/electron/guestCommandProfile.js:11` returns `null` when `arch!=='arm64'`.
- On x64: both tests fail (`false !== true`). Product behavior is correct:
  MicroVM must stay hidden on x64. The defect is the test.
- Confirm: `cd ui && node --test test/guest-command-observation-transport.test.js`
  gives rc=1 on x64. With an arm64 `process.arch` shim it gives rc=0.
- Severity: medium for CI (x64 `js` job red), none for the product. Confidence: high.

### F2. Contract fixture corpus pins out of date (arch-neutral, confirmed by running)

- `daemon-adapter/internal/ipc/policy_test.go:51-53,111` pins
  `minContractFixtureCount = 542`, but 554 legacy-classified example files exist.
  The new `capsule_state_*`, `envelope.valid.capsule_state_*` and
  `guest_command_observation*` examples are not in the additive pin lists.
  `core/tests/decode_envelope.rs:299` panics with
  `unrecognized schema prefix "guest_command_observation"`.
- Affects both arches. Not an x64 regression, but it makes `go test` and
  `cargo test` red on x64 too.
- Confirm: `cd daemon-adapter && go test ./internal/ipc/` and
  `cargo test --locked -p metaviewer-core --test decode_envelope`.
- Severity: medium (CI), none at runtime. Confidence: high.

### F3. Host channel-order and Electron harness tests red on both arches (confirmed by running)

- `ui/test/hostBindings.test.js:167` (and W2-REALAPP),
  `ui/test/rv9-elec-regressions.test.js` and `ui/test/w3-control-timeout.test.js`
  fail with an arm64 shim too. The registration of the new
  `metaviewer:guest-command.observation` channel appears to have shifted the
  expected first channel. Not x64 specific. Severity: low to medium (CI).
  Confidence: medium (the arm64 result is simulated, not from a real arm64 host).
